# Phase 1 plan: GC-managed object model (rearch/v8-chase)

## Goal

Replace the `Rc<RefCell<Object>>` object model and cycle collector with an
engine-owned tracing GC heap and single-allocation objects with inline
property slots, on branch `rearch/v8-chase`, so that Phase 3 (speculative
optimizing tier) can be built on cheap allocation, stable engine-owned
layouts, and freedom from per-copy refcount semantics. Program context and
owner decisions are recorded in
[docs/v8-chase-2026-10-15.txt](/big/Code/trust-js/docs/v8-chase-2026-10-15.txt):
target Node/V8 on framework workloads (ARM64 primary, x64 secondary),
object model before tier, big-bang branch permitted, `main` stays shippable.

## Success Criteria

- Full lib suite green and Test262 pass count at parity with `main`
  (same subsets, no new failures; skips only where `main` skips).
  Downstream crates (trust-js-host/runtime/web/node/wasm) build **and
  their tests pass** — I5 teardown executes there, not in the engine.
- Vue/React/Djot fixture elapsed times no worse than `main` beyond a bound
  the owner explicitly accepts at the merge review (target: parity or
  better; P1 is expected to be roughly elapsed-neutral).
- Vue whole-process instructions reduced by at least the threshold fixed
  at S0 exit from the ownership-cost bucket measurement (see S0; baseline
  3.298e9 instructions, 22.49e6 cache-misses; Node 0.737e9 / 2.72e6),
  paired runs, at equal-or-better elapsed. No "measurably below" vagueness
  survives S0.
- Peak RSS and GC time bounded: peak RSS on fixtures within the bound set
  at S0 (mark-sweep without compaction is expected to raise it vs
  refcounting — bound it explicitly, e.g. ≤ +25% unless re-justified),
  total GC time ≤5% of fixture elapsed, max single pause recorded.
- No `Rc<RefCell<Object>>`, cycle collector, refcounted `LStr`/symbol/
  bigint payloads, or `PackedValue`/`Value`-enum dual representation
  remains in production paths; one tagged execution word, one heap,
  copying a tagged word is always free (no incref/decref anywhere,
  including generated code).
- Embed API (`feature = "embed"`) restored; x64 validated on zombie.
- GC stress mode (collect on a small allocation budget) plus heap
  verifier pass the lib suite (see Validation Plan for what each proves).
- Sustained-allocation workload (large retained heap + repeated temporary
  allocation) stays inside the S0-set RSS/pause bounds — the new collector
  is judged on the churn refcounting used to absorb for free, not on the
  old collector's 1%.
- wasm32: sustained allocation inside a single evaluation stays within a
  bounded memory budget in an actual wasm32 run (mechanism decided at S0;
  native builds of the wasm crate do not count as evidence). **Retired
  (owner, 2026-10-18): 64-bit targets only; see the S6 deviations.**

## Approach

### Where we start

(Surveyed 2026-10-15 by direct reads after three delegated survey runs
failed; re-verify citations when touching code.)

- Two value representations: an ergonomic `Value` enum
  ([value.rs:113](/big/Code/trust-js/crates/trust-js/src/value.rs:113)) for
  execution and NaN-boxed `PackedValue` for storage
  ([value.rs:166](/big/Code/trust-js/crates/trust-js/src/value.rs:166)),
  with conversions between them. `Value::Obj(Gc)` is the *only* object
  variant: functions, proxies, Maps, typed arrays, errors are all the one
  `Object` struct discriminated by `call`/`exotic` fields — there are no
  per-kind object types to migrate separately.
- `Gc` is `repr(transparent)` over `Rc<RefCell<Object>>`, explicitly
  designed as the seam where "the collector and memory-management policy
  can observe the release of a final reference without changing any of the
  thousands of handle users"
  ([gc_handle.rs](/big/Code/trust-js/crates/trust-js/src/gc_handle.rs)).
  `Object` ([value.rs:1858](/big/Code/trust-js/crates/trust-js/src/value.rs:1858))
  carries an `Rc<GcState>` back-reference, `Props` (entries `Vec` + boxed
  element buffers + shared layout `Rc`), and per-object GC fields — 2+
  allocations and several pointer hops per object.
- Collection today = refcounting + cycle collector (weak registry, root
  classification by internal strong counts, edge snapshots in
  [gc_edges.rs](/big/Code/trust-js/crates/trust-js/src/gc_edges.rs),
  ephemerons, side-table sweep in
  [gc_sweep.rs](/big/Code/trust-js/crates/trust-js/src/gc_sweep.rs)) plus a
  non-moving nursery for young cycles
  ([gc_generational.rs](/big/Code/trust-js/crates/trust-js/src/gc_generational.rs)).
  The `trace_gc` edge functions in `gc_edges.rs`/`gc_native.rs` are the
  best existing *starting* inventory of heap edges — not a complete
  tracing contract: `HostGc` permits omitted handles (refcounts retain
  them today), `GcEdgeSink::value` follows objects only (string/symbol/
  bigint payloads have no edges yet), and opaque storage (native closure
  captures, caches, `Box` payloads) is unaudited. Under tracing, omission
  = use-after-free, so S0 audits opaque storage and S2 makes enumeration
  mandatory with enforceable declarations (see Decision 2). Measured
  collection cost is ~1% (Phase 0) — of a collector whose short-lived
  garbage refcounting already reclaimed; it prices neither the new
  collector nor generational collection's future value.
  Refcounts are load-bearing outside GC: ownership heuristics read
  `Rc::strong_count`
  ([array_binding.rs:14](/big/Code/trust-js/crates/trust-js/src/array_binding.rs:14)),
  and `LStr` performs unique-owner in-place append
  ([lstr.rs:312](/big/Code/trust-js/crates/trust-js/src/lstr.rs:312)).
- Strings are a custom refcounted thin pointer (`{strong, len, cap}`
  header, strong count at offset 0; JIT reads `LEN_OFF`/`CAP_OFF`,
  [lstr.rs:6](/big/Code/trust-js/crates/trust-js/src/lstr.rs:6)); symbols
  and bigints are `Rc`. Until these migrate, tagged-word copies are not
  free and `emit_exec_clone` cannot become a no-op.
- Execution/threading facts (correcting the previous draft): every source
  coroutine lowers to `VmCoro` "without reserving an OS thread"
  ([coroutine.rs:4](/big/Code/trust-js/crates/trust-js/src/coroutine.rs:4)),
  so generators/async always run the bytecode VM even at `--tier=interp`;
  `GcHeap = Rc<GcState>` is not `Send`. The live complexity is *several
  heaps/realms on one thread*: ShadowRealm, `ACTIVE_GC_HEAP` switching
  ([value.rs:2505](/big/Code/trust-js/crates/trust-js/src/value.rs:2505)),
  and heap selection from prototype at object creation. Remaining
  `thread::spawn` uses (JIT/regex helpers) must be confirmed Value-free
  in S0, but cross-thread object death is not the top risk.
- 136 side tables are keyed by object address (`Map<usize,…>`): under a
  free-list heap, a new object can reuse a freed address and inherit
  stale entries (`class_info`, `construct_ics`, `array_buffers`,
  `map_data` at
  [interpreter.rs:3320](/big/Code/trust-js/crates/trust-js/src/interpreter.rs:3320),
  …). Every such table needs a sweep hook from the first heap stage, and
  several are payload-migration candidates with their own speed payoff
  (Vue makes ~100k `Map.get/set` calls, each paying an address-hash
  lookup before the real one).
- Disconnected prior art to evaluate, not ignore:
  [tagged.rs](/big/Code/trust-js/crates/trust-js/src/tagged.rs) (tagged
  word, handle-table `HeapRef`, root/deopt scaffolding),
  [heap.rs](/big/Code/trust-js/crates/trust-js/src/heap.rs) (checked
  central-heap prototype), `heap-bridge` feature, and the trace machinery
  above. Prior review
  ([architecture-reassessment-20260928.md](/big/Code/trust-js/docs/architecture-reassessment-20260928.md)):
  heap rewrite is a hypothesis — measure first, migrate fully-connected,
  no permanent shadow heap. Census tooling exists
  (`architecture-diagnostics`; see
  [object-layout-inventory-20261006.txt](/big/Code/trust-js/docs/object-layout-inventory-20261006.txt)).
  Both that review and
  [node-compiler-comparison-2026-10-14.txt](/big/Code/trust-js/docs/node-compiler-comparison-2026-10-14.txt)
  predate Pilot C (shapes now encode descriptor class; carried over).

### Key decisions (recommended; S0 spike may overturn 0–1 with recorded evidence)

0. **Rooting: conservative native-stack scanning + precise heap, under a
   written scanning contract.** Rust locals holding `Value`/`Gc` are
   found by scanning the native stack (including registered `stacker`
   segments) and a spilled register snapshot at collection entry; page
   metadata resolves interior pointers to cells. Rust-*heap* containers
   (`Vec<Value>` buffers, side tables, `Box`/`Rc` payloads, VM operand
   stacks) are traced explicitly or registered as root ranges — scanning
   does not find those. **Scanning is not sound "by construction"**:
   optimized code can retain enough information to reconstruct a pointer
   without keeping a recognizable word, and conservative collectors
   "require mild restrictions on both the source code and the compiler"
   (Boehm, https://hboehm.info/gc/issues.html — most aggressive optimizing
   compilers violate the restriction for some optimized code). S0 must
   therefore produce, and S1 must encode, an explicit contract:
   (a) supported compiler/ABI assumptions recorded (rustc/LLVM, targets,
   codegen settings the engine ships);
   (b) the recognized reference forms — raw cell pointers, tagged words
   (tag-masked), interior pointers within cell bounds — and the source
   rules that keep references in those forms across allocation points
   (no hiding pointers via integer round-trips or offset arithmetic;
   the 629 `Rc::as_ptr` sites and address-keyed `usize` tables are
   inventoried against this in S0);
   (c) the register-spill protocol at collection entry;
   (d) how JIT frames comply (I7: registers never hold sole references).
   Adversarial tests (only-reference-in-register, derived interior
   pointers, split enum payloads) are *evidence for* contract compliance
   on the shipped toolchain, never a substitute for the contract.
   Fallback if the contract cannot be made credible: precise handle
   scopes — where a scope roots *all* locals created inside the native
   function (temporaries included, via a scope-registered handle stack),
   not just entry arguments. wasm32 cannot scan its stack: S0 decides
   the in-evaluation collection mechanism (task-boundary-only collection
   is *not* assumed sufficient — see Success Criteria wasm32 test);
   candidates are shadow stack or wasm-only handle scopes.
1. **Tagged pointer values, non-moving mark-sweep v1.** One 64-bit word
   (evolve `PackedValue`/`tagged.rs`; f64 numbers unchanged; heap payload
   = direct pointer into GC pages). Rejected for v1: universal
   handle-table `HeapRef` (indirection tax, 20-bit ≈1M-object cap);
   moving/copying collection (incompatible with Decision 0). Non-moving
   generational collection *is* compatible with conservative roots and
   may be valuable once tracing inherits the short-lived churn
   refcounting absorbs today; deferred beyond P1 because its value is
   unmeasured (S0 sizes the churn), not because it is impossible.
2. **Ownership switches for all objects at once via the `Gc` seam;
   layout improves afterwards, family by family.** `Gc` becomes a `Copy`
   pointer to a GC cell; cell payload initially keeps today's `Object`
   layout behind a `GcCell` providing the existing `.borrow()` API, so
   handle users compile unchanged. Trace descriptors start from
   `gc_edges.rs`/`gc_native.rs` `trace_gc` functions (audit in S1
   alongside `tagged.rs`/`heap.rs`/`gc_handle.rs`) but become a complete,
   mandatory contract at S2: `HostGc` omission fallback deleted,
   primitive-payload edges added, opaque storage (closure captures,
   caches) traced via required callbacks or forbidden from holding
   values. Where the type system can enforce declarations (descriptor
   consts per cell kind, a registry every Rust-heap value container must
   join), it must — a verifier walking the collector's own descriptors
   cannot detect fields those descriptors omit, so completeness is
   proven by registry audit against the S0 inventory, not by the walk.
   The foundational host-root/trace API is an S2 deliverable; S6 embed
   work is then only surface polish. No dual `Value::Obj` variants, no
   cross-heap edges (I6 extended to edges).
3. **Single-allocation layout (after ownership).** Header (shape,
   prototype, flags incl. `ic_plain`, compact call/exotic tags) + inline
   slots (count from S0 census) + overflow pointer; dense elements keep a
   separate buffer. Shapes/Pilot C class encoding carry over; all layouts
   engine-defined with stable offsets (JIT stops probing `Vec`/`RcBox`).
4. **Strings/symbols/bigints migrate with ownership, not "later";
   JS string accumulation is solved at S0, before ownership moves.**
   `LStr` becomes a GC cell kind (header keeps len/cap offsets the JIT
   reads; strong-count word retired). The hard part is JavaScript-level
   `s += x`: today `LStr`'s uniqueness check
   ([lstr.rs:311](/big/Code/trust-js/crates/trust-js/src/lstr.rs:311))
   proves in-place append invisible to aliases; free tagged copies
   destroy that proof, and a Rust-side builder alone does not preserve
   amortized `+=`. S0 selects the concrete replacement (candidates:
   builder-until-frozen with `+=` fast path on unshared builders,
   rope/cons representation for accumulated strings, or a GC-supported
   sole-reference proof) and validates it with scaling tests (increasing
   input sizes, aliasing patterns — not one fixture) before S2 moves
   string ownership. Quadratic copying discovered after S2 is a plan
   failure, not a tuning item.
5. **Reuse before rewrite; GC implemented in-crate** (engine core keeps
   minimal dependencies; no external GC crate).

### Invariants (review checklist for every stage)

- I1. Any heap reference live across an allocation is discoverable by the
  collector: on the scanned native stack/registers, in a traced heap
  field, or in an explicitly registered root range (Decision 0). Rust-heap
  containers holding values must be registered or traced — never scanned
  by accident or assumed found.
- I2. Every heap edge is traced via a per-family layout descriptor;
  coverage enforced by GC stress + heap verifier (see Validation).
- I3. WeakRef/FinalizationRegistry/WeakMap behavior preserved within
  ECMA-262 §9.9 liveness freedom; ephemeron fixed point retained.
- I4. Generated code and IC cells never cache raw interior pointers across
  possible collections; they re-derive from tagged words.
- I5. Host-resource teardown must not depend on `Drop` timing: audit every
  `Drop` reachable from object fields; explicit finalization paths;
  downstream-crate tests are the enforcement.
- I6. One authoritative heap per family *and no edges between heaps*: from
  S2 on there is exactly one object heap; bridge mechanisms are
  within-stage only with named exits.
- I7. JIT-produced values in registers are never sole references; the
  canonical frame/operand slots are the owning roots (already true —
  preserve it and test it under GC stress with JIT on).
- I8. Every address-keyed side table has a sweep hook (or is re-keyed/
  moved into payload) before the first stage that can free its keys;
  address reuse must never resurrect stale entries.
- I9. Collection never runs with an outstanding `GcCell` borrow, and
  partially-initialized cells are always traceable. Preserving the
  `.borrow()` API does not preserve allocation safety: existing code
  borrows mutably while allocating (see Revision notes), and today's
  collector panics if entered during a mutable borrow. Rules: allocation
  points are explicit; inside a bounded no-GC region (the `tagged.rs`
  `NoGcScope` scaffolding is prior art) allocation may proceed but
  collection is deferred via a pending flag, honored at region exit;
  debug builds assert on violation. Cells are allocated in a
  descriptor-safe empty state and published only after initialization,
  so a collection at any allocation point sees only well-formed cells.
  Specified in S1, enforced from S2 — not retrofitted.

Recorded deviations (S1 review, 2026-10-15; details in the program record):

- I9: a deferred collection runs at the next allocation or collection
  request after the outermost no-GC region exits, not at region exit —
  exit is not an allocation point, so collecting there would add a
  safepoint the contract does not have.
- Decision 2 registry: unconditional trace roots are for true roots only.
  Side tables holding values owned by a cell (Map/Set data, WeakMap
  entries, FinalizationRegistry held values) register owner-conditional
  edge sources; in-cell weak data is reported by descriptor `weak`
  callbacks. A side table traced as a root would keep cycles through it
  alive forever.
- Decision 0 stacker choice: option (a), `gc_core::grow` with exact
  segment bounds; engine grow call sites switch to it at S2. Collections
  requested on an unregistered segment defer.
- wasm32: the S0-deferred prototype run is re-deferred to the S2 wasm32
  acceptance gate (this box's rustc/LLVM has no WebAssembly backend).

Recorded deviations (S2, 2026-10-16; details in the program record):

- S2 also moves environment records (Env) onto the GC heap as cells.
  Rust-local Env handles are pervasive, and the conservative scan only
  discovers handles into the GC heap; without this, I1 cannot hold.
  S4 still owns the tailored environment *layout*.
- Collections run only at interpreter safepoints, never on allocation;
  GC stress therefore means "collect at every safepoint".
- Rust-heap Value containers live across a safepoint use a rooted
  container type; stress plus poisoning finds the sites (I1 audit).
- Multi-heap semantics as defined at step 3c: a ShadowRealm's interpreter
  allocates in its parent's heap (one heap per Agent) and the root of the
  ShadowRealm tree collects for all of it. Object edges between Agents
  (separate Engines) are out of contract (I6).
- "Lib suite green under gc-heap" is met with gc-heap-only ignores that
  carry their reason: JIT tests until S5; tests of the reference-count
  model (counts, release timing, eager death notification, its collector
  and nursery) and of contracts S2 removes (cross-Agent edges, the HostGc
  omission fallback, a callable lease rooting captures, handles that
  outlive their Agent). They retire with the old model at S6.
- Decision 4's string accumulation mechanism is replaced at step 4d:
  "frontier append" instead of the builder-cell typestate. A flat string
  cell records how far its buffer has been written (its frontier).
  Appending to a string that ends at its buffer's frontier, with spare
  capacity, writes past the frontier, advances it and returns a view of
  the same buffer; any other append copies into a new buffer with
  geometric capacity. Bytes a string can read never change afterwards,
  so in-place append needs no uniqueness proof and no slot typestate:
  an alias keeps its own length, and its own later append copies.
  Amortized += is preserved at the cost of one small view cell per
  in-place append. The typestate is rejected because every read path of
  every slot kind (locals, captures, properties and their hundreds of
  readers) would have to freeze builders, and one missed path would make
  an in-place append visible through an alias.
- The HostGc omission fallback is gone from gc-heap, where a host keeps
  alive exactly what its mandatory HostTrace reports, and the type system
  requires that enumeration in both builds (OpState::put, ResourceTable::
  add, opaque native closures). The counted build's cycle collector still
  treats an unreported handle as a root; that fallback retires with it at
  S6 rather than being emulated there.
- "GC stress + verifier green over the suite" runs each lib test in its
  own process at stress interval 1 (debug build: verifier and poisoning
  at every collection). Assertions about *when* collections or cleanup
  jobs happen are skipped under stress; tests whose cost is quadratic at
  interval 1 (deep recursion, long chains, allocation loops) run at
  interval 100 instead (1000 for the heaviest four).
- The S2 wasm32 acceptance run is blocked as at S0 and S1: this box's
  rustc/LLVM still has no WebAssembly backend and no wasm32 std. It
  moves to the S6 wasm32 acceptance gate, with a wasm32-capable
  toolchain as its prerequisite (owner).

Recorded deviations (S3, 2026-10-16; details in the program record):

  payload homes (proxy, typed-array and module-namespace state), one
  payload mechanism for all. Measured: its address lookup is a few

### Working agreements (all agents)

- Branch `rearch/v8-chase` only; one agent at a time. **Syncing `main`
  into the branch happens only at stage boundaries**, and each sync is
  treated as a semantic merge (pilot commits depend on `JitLayout`/RcBox
  meanings, so conflicts will be in meaning, not text): after every sync,
  re-run the current stage's full gate before new work; record syncs in
  the stage table. If sync cost exceeds value mid-P1, freeze syncs until
  S6 and record that instead. Never force-push.
- One stage per commit series; never mix stages. Follow
  [AGENTS.md](/big/Code/trust-js/AGENTS.md) layering and
  [DIAGNOSTICS.md](/big/Code/trust-js/DIAGNOSTICS.md) tooling; required
  instructions must not depend on untracked docs (hence this file is
  `.txt` and tracked).
- Builds: incremental no-LTO
  (`CARGO_PROFILE_RELEASE_LTO=false CARGO_PROFILE_RELEASE_CODEGEN_UNITS=16`);
  fat LTO only for recorded acceptance pairs (benchmarks/README.md).
  Fixture runs use the engine binary `target/release/trust-js`, CPU-pinned.
- Every perf/memory claim records machine, revision, tier, flags,
  workload in
  [docs/v8-chase-2026-10-15.txt](/big/Code/trust-js/docs/v8-chase-2026-10-15.txt).
- A stage gate failing twice for one root cause: stop, record blocker
  here, surface for review; do not widen scope to work around it.

## Validation Plan

Standing commands (repo root; `<bin>` = `target/release/trust-js`):

- `cargo test -p trust-js --lib --features embed` (add `,gc-heap` during
  S1–S5); downstream: `cargo test -p trust-js-host -p trust-js-runtime
  -p trust-js-web -p trust-js-node` at S4/S6 gates.
- `cargo clippy --offline --locked -p trust-js --all-targets --features embed -- -Dwarnings`
- `cargo run -q -p test262-runner -- <subsets per stage>` vs `main`,
  identical subsets, zero new failures.
- `cargo run -q -p trust-js-difftest -- --seed 7 --count 150`.
- Fixtures from S0.0 onward: `taskset -c 5 <bin> --tier=jit
  benchmarks/fixtures/{vue,react,djot}.js`; outputs identical to `main`
  except `elapsed_ms`; paired fat-LTO A/B (≥11 alternating pairs,
  internal medians) at S6, tripwire form at S2/S3.
- `perf stat -e task-clock,cycles,instructions,cache-misses,branch-misses`
  + peak RSS (`/usr/bin/time -v`) on Vue: branch vs `main` vs `node`,
  at S0 (bucket), S3, S6.
- **Sustained-allocation workload** (new fixture, S0.0-preserved style):
  large retained heap + repeated temporary allocation; report post-GC
  live bytes, fragmentation (allocated vs live pages), pause
  distribution (existing GC pause histogram), total GC %. This, not the
  old collector's 1%, is the new collector's exam. Mandatory S2→S6.
- **wasm32 acceptance** (S2 and S6): real wasm32 execution of a
  sustained-allocation script inside one evaluation, memory bounded per
  the S0-decided mechanism. Native test runs of the wasm crate are not
  evidence.
- **GC stress + heap verifier + poisoned free cells** (S1 deliverables,
  mandatory from S2): stress proves descriptor coverage on executed
  paths; poisoning turns use-after-free into immediate failures. Two
  honest limits: the verifier walks the collector's own descriptors, so
  it cannot detect omitted fields (completeness comes from the
  Decision 2 registry audit vs the S0 inventory); and no test proves
  native-local rooting on unexecuted paths — that rests on the Decision 0
  scanning *contract* (documented compiler/ABI/source restrictions),
  with adversarial tests as compliance evidence only. **The S0 contract
  + spike and the S2 stress/verifier/registry combination is the
  highest-risk validation in the program.**

## Risks / Open Questions

- **Rooting completeness (top risk).** Conservative scanning rests on
  restrictions the compiler does not guarantee (Boehm): optimized Rust
  may keep sole references in registers, split enum payloads, or
  reconstruct pointers from non-pointer data. The Decision 0 contract
  (documented assumptions + source rules + recognized forms) is the
  mitigation; tests are compliance evidence, not proof. Residual risk is
  accepted knowingly at the S0 go/no-go, or the program re-plans around
  precise handle scopes at their much larger cost. Related I9 risk:
  borrow-across-allocation patterns are pervasive in idiomatic form
  (`borrow_mut()` temporaries spanning allocating calls); the S0 retrofit
  list sizes this before S2 commits to enforcement.
- **Several heaps/realms on one thread.** ShadowRealm,
  `ACTIVE_GC_HEAP` switching, heap-from-prototype creation: cross-heap
  references must be impossible or explicitly handled before S2 (I6);
  S0 inventories, S2 defines.
- **Refcount-observable behavior.** `strong_count` heuristics,
  `LStr` unique append, deterministic `Drop` teardown: each needs a
  semantic replacement or proof of optimization-only status (S0).
- **Scale.** ~174k lines mention `Value` across 86 non-test files; the
  `Gc`-seam strategy exists precisely so most of them don't change in S2.
  Layout stages then touch payloads family by family with measurements.
- **Elapsed-neutral / memory-up outcome.** P1 may cut instructions while
  fixture elapsed stays flat (builtin outliers) and RSS rises
  (mark-sweep). Success Criteria bound both explicitly at S0 so the
  merge review judges against numbers, not vibes.
- Open questions for S0 (block their stage, not plan approval): inline
  slot count/header budget; nuclei audit outcome (`tagged.rs`/`heap.rs`);
  embed handle ergonomics for TRust host code. (String accumulation and
  wasm32 collection moved from open questions to S0 *decisions* — see
  Decisions 0/4.)
