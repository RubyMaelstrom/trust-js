Important architectural observations to re-examine
-------------------------------------------------
Root category-analysis inputs are ANY; property reads generally produce unknown
categories. Hot admission does not feed argument-type feedback into compilation.
compile_for_optimizer currently uses an empty inliner plan; the optimizer's
InlineGuard executes the original fallback call. True speculative inlining needs
logical-frame reconstruction, arguments/caller/completion and GC contracts.

MakeObject and MakeArray ALREADY use dedicated helpers with direct moves from
canonical slots; they do not generally round-trip via the generic opcode helper
or temporary Vecs. Do not propose merely adding the helpers that already exist.
Investigate actual allocation/representation and specialization costs.

Cranelift memory alias-region changes require consistent tagging of ALL matching
loads/stores; an unregioned load is not safely invalidated by a differently
classified store. trusted is not equivalent to freely movable. No alias-region
change has been implemented here.

The user linked https://perryts.com/en/blog/cranelift-to-llvm/ as inspiration,
NOT a request to adopt LLVM. It was already read. The useful lesson is the
front-end/IR and opaque-helper work needed to benefit from a code generator.
Its corrected September numbers retract the older 24.6x Node claim (93/95 ms
tie). It concerns AOT TypeScript, not full dynamic JavaScript.
