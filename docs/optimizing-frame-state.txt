Operand SSA and frame reconstruction — implemented boundary and remaining work
==========================================================================

The stack10 source implements the proven-live operand suffix analysis and lowering
described below. All 1,554 feature-enabled default-mode debug/release tests pass. Full
forced Test262 completed with 53,572 passes, two existing legacy-reflection failures and
four skips; the native creation/array-write coverage gaps and performance gate remain open.
This is NOT a claim that deoptimization, inlining, OSR, suspension reconstruction or
ownership elision is complete. Safepoints still use the canonical packed-owner frame.

The critical distinction
-------------------------
Cfg::stack_depth_at is exact on ordinary entry/normal flow, but handler depths can
be upper bounds. jit_unwind_target and jit_complete_target deliberately restore
min(saved_handler_depth, actual_remaining_depth): a protected operation may have
consumed operands before failing. A landing-pad reload of the entire static depth
can resurrect moved owners, read uninitialized cells and later double-drop them.
This is not fixable by asserting that every helper throws with its original stack.

The implemented solution is SSA for a PROVEN-LIVE SUFFIX over a canonical opaque
prefix. Keep the actual runtime sp independently from compile-time slot labels.

Let D be the CFG's logical depth at a PC, and F the first known-live SSA slot label.
Only [F,D) is represented by owning SSA values; labels below F are opaque canonical
memory. A label i maps to actual_sp + 8*(i-D), NEVER stack_base + 8*i. Therefore a
shorter exception-restored prefix does not change the position of its live suffix.

Entry has D=F=0. A catch/finalizer entry knows only the completion words its router
has just pushed (one exception/return value, two jump words, or no bare-return word).
Other dynamically dispatched abrupt-jump destinations must conservatively admit an
opaque prefix. Multiple entry kinds use their minimum guaranteed suffix, not their
largest static depth. Different normal predecessors join at the same D; F takes the
maximum incoming floor. jit_optimizing_stack.rs supplies the bounded fixed-point analysis.

Normal stack effects with P pops and Q pushes map a known suffix length K to
max(K-P,0)+Q. Native fast lowering requires all inspected inputs to be in the known
suffix. If P>K, retain the existing checked operation and learn its Q normal-result
words. Do not use a static upper bound as permission to read an opaque operand.

Publication and edges
----------------------
1. Before every observer/helper/GC poll, publish dirty locals and every outstanding
   owning suffix word at its actual-sp-relative position. There is no hidden root
   in an integer SSA value from the collector's perspective.
2. A normal checked return may reload its proven suffix from the returned sp. An
   exceptional return MUST branch to the canonical unwinder first; never reload
   the success-path prefix when a helper has already consumed its arguments.
3. Dynamic completion dispatch reloads only the suffix proved for that destination,
   from the ACTUAL returned sp. Never republish pre-call values over completed effects.
4. An edge that raises F forgets SSA owners into the opaque prefix. Publish those
   words before taking that edge. Conditional edges may conservatively publish the
   union needed by either successor, but may not lose ownership on the untaken arm.
5. Code-emission state is path-specific: emitting a fast push/pop must not change the
   slow arm's incoming logical depth/floor. All guards precede ownership effects.
6. Unknown operations remain publication/invalidation barriers. Calls can mutate
   captured/eval-visible bindings and heap facts; exception completion may replace a
   pending return, break or continue. Unreachable bytecode needs deliberate emission,
   not an unchecked zero-depth indexing shortcut.
7. Bound analysis work, slot-state space and IR growth. An analysis-budget decline
   keeps the complete existing execution tier; it is not a language/resource limit.

Ownership is a separate proof
-------------------------------
A bits-only SSA copy is not an owning copy. The first implementation must preserve
every retain/move/release exactly, including joins, self-assignment, last-reference
destruction, weak metadata and lazy property prototype materialization. Keeping words
in registers does not by itself justify eliminating their reference counts.

Later ownership elision needs value liveness AND an owner-location/frame-state model.
A borrowed operand cannot outlive the local version from which it was borrowed unless
an owner is transferred/retained. Materializing two owning canonical slots requires
two owners, not duplicated unretained words. A future tracing/moving heap requires
explicit root maps and relocation reloads; Cranelift cannot infer those JS contracts.
The current Rc cycle collector and host handles remain authoritative until migrated.

Inlining and deoptimization cannot be bolted on by merely concatenating bodies.
They need logical callee/realm/strictness/arguments/lexical-context records, original
and current argument state as required, pending completion and handler state, and
before-effect versus after-effect resume points. Reconstruct all logical inlined
frames without replaying getters, coercions, Proxy traps, callbacks or IteratorClose.
The existing legacy function.arguments failures demonstrate a current activation-
reflection gap; this design does not waive it or claim it fixed.

Before-effect deoptimization (frozen deopt11 development build)
-------------------------------------------------------------
The source implements a terminal native-to-VM transfer for one ordinary logical frame.
Focused tests and full library suites now exercise it, but broad validation remains open and it is not a
speculation policy. The explicit development
stress hook TRUST_JS_OPT_JIT_DEOPT_AT selects a bytecode boundary at compile time; when
unset, it adds no generated branch or helper call. It cannot select suspending or
baseline-inlined bodies. The next typed middle-end must choose guards using feedback
and precise frame states; this hook does not implement that optimizer.

The transfer publishes locals and the proven operand suffix, then MOVES the full actual
canonical operand prefix to an independent VM stack. Native final_sp immediately becomes
stack_base. The VM owns further stack growth and leftover destruction; the original
native teardown still owns local slots, this, code residency and the real call frame.
Existing prepared References, captured/root versus current lexical environments and
in-progress class/disposal state stay attached to this invocation. There is no argument
binding, FunctionDeclarationInstantiation, new FnFrame or replay of completed effects.

Only handlers above JitCtx::handler_floor enter the VM driver. Caller handlers must
remain untouched even if the callee and caller share a context. A caller's activation
sidecar likewise cannot be reused by a stateless callee just because its pointer is
non-null. The VM finishes all callee completions, then returns directly to the native
success/error epilogue; a native unwind or resume of the original operation would be a
second, invalid completion. The existing proper-tail-call trampoline stays authoritative.

The stress tests force individual PC boundaries through real Call entries,
check exact results and effect traces against an independent interpreter, and require
actual bailout coverage. They cover pending returns/throws/labelled jumps, IteratorClose,
prepared assignment References after RHS resolution changes, mapped arguments, eval,
TDZ, lexical captures, parameter defaults, tail calls, cyclic ownership and a template
caller sharing handlers/activation state with an optimizing callee. The first run passed
six tests and failed two fixture coverage checks: a with-statement fixture was not
bytecode-eligible, and an uncaptured catch binding had not created a caller sidecar.
The reference fixture now uses direct eval to introduce a shadowing local AFTER the
global Reference is resolved; the caller fixture captures its catch binding in a closure.
Both retain their native-path assertions and pass, including an explicit foreign-sidecar
entry count. An expanded cyclic-owner sweep passes on both normal return and throw.
The original failure log is retained; no semantic assertion was waived. The full library
suite now passes 1,562 tests in both debug and release with the feature enabled (the
ordinary default tier plus explicit native-path fixtures). The feature-off debug suite
passes 1,517 tests. Full Test262 under forced optimization and TRUST_JS_OPT_JIT_DEOPT_AT=7
completes with 53,572 passes, the same two known staging/sm legacy-reflection failures,
and four skips. The uncapped schema-2 report preserves every failed/skipped path and
reason; no skipped test or failure was waived by this work. This is the full suite under
the stress configuration, not a claim that every case actually entered a native bailout.
The release headless browser, also forcing boundary 7, completed all 20 official
Speedometer 3.1 suites / 58 steps in an explicitly functional-uncontrolled run. It
overlapped Test262, so its timing is not performance evidence. These tests are not a
performance acceptance, visual-accuracy check, or x64 execution gate.

Required checks before integration
----------------------------------
* Normal loops and multi-predecessor joins with unequal known-suffix floors.
* A destructuring/iterator operation consuming below its installed handler depth.
* Nested catch/finally, overridden returns, break/continue and IteratorClose throws.
* Guards after previous completed effects; no duplicate coercions or getter calls.
* Captured bindings, direct eval, TDZ, strictness, realm changes and native callbacks.
* Self-valued fields, shared and final owners of every packed value type, collection
  at loop polls and calls, weak references and job-boundary kept-alive behavior.
* Structural/native-path assertions, tier differential checks, pinned full Test262,
  default-tier/browser regression checks and both ARM64/x64 execution gates.
* Interleaved full-application release measurements of score, latency, compilation,
  code size and memory; no promotion from a kernel or an aggregate-only improvement.
