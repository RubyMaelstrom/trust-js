Optional baseline CFG-region provenance
======================================

Build with optimizing-jit and set TRUST_JS_OPT_JIT_COVERAGE=1 before process startup.
The engine exposes unstable_execution_coverage_json() for an explicit cold snapshot;
this neither collects nor schedules tasks and observes no JavaScript object state.
The control is off by default. No production compiler/admission policy changes here.

A bit means that control entered a semantic CFG block, or a fused native region
that could execute it, before effects. A native fusion conservatively marks all
potential original blocks. Later operations after a throw may therefore be marked
hot. These are region-entry observations, never per-op success or complete-call
counts. Empty ICs do not supply execution evidence. Getters and proxies still enter
their containing blocks even if the operation throws or creates no IC proof.

UnseenInWindow applies only to this exact baseline bytecode version's instrumented
collection window. Previous AST calls, a different flattened inline version, and
separate optimizing-clone native/VM-rescue executions are outside that window.
That exclusion concerns positive entry bits. AST and successful shortcut bypasses
conservatively invalidate all retained live primary/inline Sources, including when
the selected shortcut version is Frozen; they never mutate frozen snapshots.
An optimizer clone freezes original scalar bitmap/status/source-version lineage;
it does not retain mutable source feedback or reuse the source runtime-entry ID.
It retains exact original bytecodes, slots, source positions and inline metadata.
No entered region means Unknown. Any uncovered semantic route makes unentered
blocks sticky Unknown; positive bits remain conservatively hot. AST body fallback,
binding-getter/record-getter/constructor/initializer elision and live-Source optimizing entries
invalidate explicitly. Frozen clone metadata never changes after such execution.

The source profile is an Agent-thread union across its Realms and closures, with
no raw Realm identities or JavaScript owners. Primary, flattened and fragment
versions allocate distinct checked thread-local IDs. A fragment profile does not
project onto the enclosing full-function graph. Surrounding/alternative parent AST
loop iterations are outside that fragment Chunk window; matching source spans do
not transfer observations. A fragment's own unmapped execution must invalidate it.
Current native region selection excludes fragments. Resumed/interrupted/suspended
entries contribute only their entered containing regions; no full call is inferred.
Before-operation polls may stop execution before a native marker; VM stop_at stops
before marking its target operation. Scalar marking changes no completion, owner,
handler, lexical, call-position or GC state.

Limits: 65,536 operations and 8,192 semantic CFG blocks per version; 1,024 live
versions and 16 MiB combined source/frozen storage per owning thread. The fixed
u16 PC map, u32 leader table and entered bitmap are built from the shared linear
semantic block layout, without stack/dominance/loop solvers. Oversize/invalid
layouts, quota or ID denial preserve Unknown; no source/function name changes
these bounds. Native/prepared bodies pin only scalar feedback allocations. The
bounded Weak directory neither retains JavaScript nor executable code. Source
payload survives Chunk destruction while a native lease exists; Weak allocation
headers remain charged until cold directory cleanup. Shared frozen Rc snapshots
reserve storage once and release it at the final owner.

Storage metrics count Rust-requested container capacities and owned payload/header
bytes, excluding allocator rounding/bookkeeping. Refcount headers use the project's
existing two-usize diagnostic accounting model. The combined quota includes fixed
directory capacity and dead Weak headers; managed-memory traversal separately
deduplicates shared source/snapshot allocations and excludes private Rc headers,
consistent with its existing category contract. Temporary returned JSON strings
are caller-owned, not retained profile storage. Diagnostic snapshot failures appear
as omitted rows and increment the same saturating storage/layout/ID denial count.

Ordinary builds compile out the facility. Feature-enabled/control-off builds add
optional Chunk/native metadata header fields and cached scalar control/handle checks
at compilation, VM slice dispatch, AST entry and successful shortcut boundaries.
The disabled checks perform no added callable borrow or Function-slot scan. There
is no bitmap/directory allocation,
native marker/call, JitCtx field or frame storage. Relevant header sizes and offset
changes must be recorded in validation; native equivalence permits those explicit
layout/address constants. The off VM slice selects its existing non-recording loop
once at dispatch. Enabled ARM64/x64 markers preserve canonical storage, preserve
ARM NZCV, and use only scratch registers at established entry boundaries; x64 OR
marks run after predecessor conditions have already transferred control.

Collection is compiler optimization feedback. Its overhead, metadata retention,
startup and compilation costs must be measured; instrumented timings cannot be
performance acceptance. Future region selection must consume one immutable exact
snapshot, keep Unknown regions, guard future cold-path execution with complete
terminal VM recovery, and credit no optimized work beyond a cut. Coverage does
not relax global suspension/disposal exclusions or prove future dead code.
