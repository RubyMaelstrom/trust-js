Object/value runtime — first implementation batch, 5 October 2026
================================================================

This batch removes repeated work in the existing object and value runtime.
The measured application-component gains are modest: about 2.6% less time in
Vue reactivity, 2.4% in Djot conversion and 0.7% in the EJS solver. React's
reducer is unchanged within the comparison interval. Correctness and the
repository's component regression gates pass, so the source experiment is
retained. It does not establish the requested major engine improvement or an
8–10x overall speedup; that investigation continues.

Implementation
--------------

1. Keep packed owners through named reads and native argument transfer.

   The native named-property helper reads ordinary cached data directly into
   a PackedValue. It borrows the receiver only during the non-observable IC
   probe, then releases that borrow before any getter or exotic operation.
   Those paths first acquire an independent receiver owner, so reentry can
   replace the caller's slot. Deferred function prototypes retain ordinary
   materialization. The String length shortcut also avoids widening.

   General cached native calls move argument owners into the builtin's wide
   interface instead of cloning them. Those owners remain live through the
   post-call interrupt poll and pending-tail drain. The receiver retains its
   established lifetime. Tests cover last owners, callbacks, collection,
   exceptions, pending tails, method receivers and all packed value families.

2. Share the bounded ordinary-object lookup index with the key layout.

   PropertyLayoutData owns the ordered keys and an optional immutable lookup
   table for 9–16-field shapes and constructor predictions. Instances sharing
   that layout no longer build duplicate tables. Only the initialized prefix
   is visible; copy-on-write mutation keeps keys and the table consistent.
   Longer/private maps keep their incremental per-object fallback, and arrays
   retain their existing element representation. Native creation measures the
   live key-vector offset rather than assuming the old Rust layout.

   Ordinary property removal also avoids allocating an empty dense-element
   sidecar merely to visit it. Memory accounting deduplicates shared layouts
   and records the new index's known capacity as a lower bound.

3. Preserve successful lexical resolution in simple binding getters.

   An eligible `return identifier` getter caches a bounded proof on its own
   UserCallable, never on a shared AST. Every scope identity and structural
   generation is checked before reading the live Binding. Weak scope pins
   prevent allocation-address reuse without retaining JavaScript values.
   With/global/import/TDZ/deep cases use ordinary Call. Failed proofs allocate
   no cache metadata; the cold path constructs it only after a successful
   lookup. Tests exercise distinct closures and Realms, eval-driven insertion,
   growth, shadowing and deletion, and live value changes.

The three directions have begun; this is not a complete representation
migration. Ordinary fields still occupy 16-byte Property records, and generic
runtime, proxy and callback interfaces still use the wide Value enum.

Continuation and evidence
-------------------------

The next investigation addresses complete proxy/callback call paths and their
value ownership, argument transfer, environment and frame work. The actual Vue
fixture repeatedly calls a Proxy setter and its reactive effect; ordinary own
data reads cover only part of that work. Existing shapes, call caches and frame
pools must be accounted for before adding another mechanism. Keeping values
packed through a whole operation and carrying already-validated call information
through its helpers are concrete candidates. A later descriptor/field layout
change needs its own evidence and native-backend correctness gates.

An exploratory profile of the preceding candidate left 3602 of 17491 samples
unresolved, versus zero of 17772 baseline samples. Its raw aggregate artifact
cannot recover missing instruction addresses. No precise category-speedup claim
is based on that comparison; the next profiler preserves address/mapping data.
Inclusive proxy/callback stacks are not treated as exclusive time or added
together. No major-gain claim follows from the current few-percent results.
