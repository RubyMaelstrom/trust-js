G1 — Explain the costs with causal, bounded diagnostics.
Record compiler phase distributions, source/expanded-IR sizes, entry counts,
checked fallback categories, ownership/guard traffic, IC invalidations and
allocation/browser work. Keep instrumentation out of acceptance timing and do
not use detailed-feedback mode as if it observed ordinary native execution.
Done when the chosen implementation has an evidence-based savings prediction
and competing explanations have been measured or explicitly rejected.

G2 — Build a connected semantic specialization path.
Use live IC/value feedback, stable operation identity, explicit effects,
ownership and recovery to eliminate repeated work before machine lowering.
Retain checked behavior, single-frame continuation correctness and budgeted
compilation. Test mutations/coercion/throw/GC/alias interactions in all affected
tiers. Do not substitute more isolated opcode helpers for this goal.

G3 — Make tier admission/publication repay their cost.
Measure compilation and post-upgrade execution separately. Address hotness,
IR expansion and call-cache refill costs as justified by the results. Verify
old-frame/code residency and retirement safety. Keep unsupported entries on
the complete established tier; never omit JavaScript behavior.

G4 — Address allocation and ownership costs in the live engine.
Measure by actual object families/sites, then remove justified overhead in
production representations. A shadow heap prototype is not a completed result.
An evidence-based decision that a moving heap is unnecessary addresses that
alternative; abandoning measurement or native ownership work does not.

G5 — Address repeated browser work independently.
Measure style lookup/allocation/invalidation fanout and geometry/render reuse
on real actions. Implement justified general changes, respecting document,
shadow, CSSOM/observer and desktop/shared boundaries. Preserve the existing
unrelated dirty invalidation work and validate terminal as well as desktop.

G6 — Establish correctness and broad performance.
Run focused tests before broader debug/release suites, Clippy and release
builds. Complete appropriate ARM64/x64, Test262, CSS WPT and live visual/
interaction gates; keep failures and skip details. Use exact frozen release
artifacts, balanced independent runs and full official Speedometer, plus
verified long-lived application interactions. Inspect every component,
memory, compilation latency and pauses. A material improvement over the
template baseline is required; recovering part of the experimental regression
is insufficient. No 60x claim without an actual matching measurement.
