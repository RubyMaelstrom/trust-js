Native named assignment results — 30 September 2026
====================================================

The preceding whole-call shortcut removed 2,770,681 SetProp helper calls
from the complete solver, but introduced 2,766,884 checked caller helpers
and made the solver 1.38% slower. It was reverted. The source reveals a
more direct gap: statement-position named stores already use ARM64 inline
own-property overwrite/creation, while the value-keeping SetProp always
used the Rust helper. Return/chain/conditional assignments therefore paid
that helper even for ordinary own writable data and scalar RHS values.

The existing store emitter now accepts the result-preserving form. Live
receiver/exotic/shape/slot/descriptor and creation proofs are unchanged.
All misses precede stores and owner acquisition. On success the property
acquires one RHS owner and the original operand owner moves over the
receiver into the expression result. Old-value/receiver decrements still
require non-final owners; alias, lazy/BigInt, exotic, descriptor and shape
misses retain the original exact-PC checked operation. No extra cache,
opcode, object layout, call dispatcher, frame omission or host dependency
is added. Baseline and SSA barrier emission share this operation. x64
retains its established checked property stores. Ordinary optimizing-JIT
selection/architecture probes remain off.

A fallback regression exposed a pre-existing PutValue rejection bug:
strict assignment ignored a false Proxy [[Set]] result. The pinned baseline
reports 0:8:false:12 across interpreter/bytecode/JIT for a fixture with six
strict named/computed/super/inherited writes, one Reflect.set and one sloppy
write; Node reports 6:8:false:12. Assignment wrappers now enforce the
reference's captured strictness after [[Set]], while the internal Boolean
result used by Reflect.set is unchanged. Profiled paths and both super
assignment paths use the same completion check. All three tiers now match
Node for that rejection fixture.
