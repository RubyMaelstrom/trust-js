Closed numeric/string advance calls — 30 September 2026
=======================================================

Decision: the scalar call prototype was reverted after a negative full-solver
comparison. The following implementation describes the frozen experiment.

Cycle19's logical-frame growth recorded 3,172,414 entry and exit helpers in
the complete EJS solver without a convincing solver improvement. Source
inspection associates a hot family with Meriyah's tiny advance function:
return e.column++, e.currentChar=e.source.charCodeAt(++e.index).
The names are incidental. The compiler proof recognizes the complete
strict ordinary body: two distinct own field increments, a primitive-string
field's exact charCodeAt, a distinct result-field assignment and return.
This is a whole-body checked call specialization, not broader AST inlining.

Chunk caches the bounded positive/negative structural proof. A bit in the
existing CallIc directs admitted bodies through the checked shared Rust
helper; ARM64 shared-frame calls remain disabled only for those bodies. The
CallIc layout, object/value representation and executable memory contract
are unchanged. The new plan cell adds 16 bytes per native Chunk; positive
plans own no object, string or AST references and charge their Box storage
in retained-memory accounting. All original body instructions and native
code remain available for every miss.

Every execution validates a current ordinary receiver, four distinct live
own data descriptors, Number increment inputs, a Number result field, a
primitive String source, writable destinations and the live exact native
charCodeAt method in the current realm. Shapes cache slot positions only;
attribute/value changes remain checked. Method replacement, getters, setters,
proxies, inherited fields, wrappers, conversions and unsupported bodies
retain the full call before any body effect. The method's own slot guard
handles String.prototype's String-wrapper exotic by its named data property,
never by an index/length shortcut. Property-only deferred values decline
before unpacking; guards cannot materialize a lazy function prototype.

Successful bodies have no JS/GC observer of an omitted call frame. The
argument stays owned on the canonical operand stack plus a local snapshot;
an additional live receiver owner is required, retaining the ordinary
frame for last-owner parameter destruction. Only one-argument calls with
an undefined this value use the shortcut: the ordinary moved entry releases
unused receiver/surplus owners before the body, and host destructors can
observe that order. A real host closure destructor regression verifies it.
The checked helper preserves the packed consume-on-completion call contract.

Due GC ticks, allocation pressure, physical stack exhaustion, pending tail
work and already pending interrupts retain full execution. Success preserves
the callee/native call GC cadence and both physical stack checkpoints,
performs both Number increments before
the native entry/exit interrupt checks, and publishes the result only after
those checks. UTF-16 reads use the existing owning bounded cache. They
allocate no GC object and run no author code. Full fallback maintains the
logical Function/Realm/context for any observer or exception. This is not
an optimizing-tier feature or a production change to the old AST inliner.
