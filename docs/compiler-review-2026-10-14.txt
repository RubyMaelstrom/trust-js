Compiler review checkpoint, 2026-10-14
====================================

This checkpoint lets the optional whole-function backend optimize an already
inlined canonical bytecode body. It also adds bounded integer interval proofs and
reuses guarded own-property metadata across effect-free control-flow paths.
Prepared callers can use baseline inlining while retaining their live activation.
The optional backend remains disabled by default. Correctness validation below
covers the first two frozen candidates and separately identified follow-ups;
browser performance acceptance is pending.

The user prioritizes Speedometer 3.1 segments and common-framework browser pages.
Selected suites are sufficient for iteration and acceptance. No full-suite run is
required for every change, and a subset must never be reported as a full score.
Synthetic profiles below identify compiler mechanisms; they do not establish an
application improvement or determine acceptance.

Implemented contracts
---------------------
A Function has a separate optional optimizing-code slot. Successful compilation
publishes an immutable clone of its selected warmed baseline Chunk, preserving
existing guarded inlines, canonical remapped slots, bytecode PCs and logical source
positions. The previous baseline stays resident for active calls and retirement.
Eight specialization misses select that warmed baseline, including its inlines.
Publication invalidates future call caches only after native compilation succeeds.
Cloned runtime/admission state is independent. Cache seeds require current epochs
and matching weak identities; compiled code adds no JavaScript object owners.
Shared inline-source metadata unregisters on final-owner drop and is counted once.

Native InlineGuard tests the actual packed callee identity, closure/global context
and required sloppy receiver category before mutating operands. A miss retains the
original call fallback. Recovery continues the exact flattened bytecode and its
canonical owners, including partially completed inline argument binding. Existing
frame-independent splice eligibility remains the limit; this does not implement
arbitrary inlining of context-bearing callees or suspended functions. The separate
experimental loop-continuation policy retains its previous no-inline restriction.

Prepared callers preserve FunctionDeclarationInstantiation. Recompilation retains
the prepared-entry contract, and post-instantiation dispatch selects the current
body. Mapped arguments, captured bindings and direct eval keep their authoritative
live environment. Parameter initialization and caller hoisting are not repeated.
The existing callee eligibility and constructor-entry restrictions remain in force.

Bounded integer intervals derive from constants and language operations, excluding
negative zero and precision-losing arithmetic. Unguarded entry samples do not become
range facts. Normal joins take hulls; natural loop headers widen or lose proofs;
dynamic completion roots begin unknown. Used proofs remove redundant numeric and
ToInt32/index conversion checks while retaining live element bounds and ownership.
TRUST_JS_OPT_JIT_RANGES=0 is an ablation. This checkpoint does not add integer SSA
lanes; that next tranche is being developed in an isolated checkout.

A separate bounded heap metadata analysis requires facts on every incoming path.
The lowering bridge uses stable receiver identities and warmed numeric own-data
reads with terminal misses. It can reuse ordinary-object, shape, slot-bound and
descriptor proofs. It still reads the current storage pointer and value and checks
the live result category. Calls, polls, generic helpers and mutation paths clear
proofs; private-slot preservation does not imply immutable heap contents.
TRUST_JS_OPT_JIT_HEAP_PROOFS=0 is an ablation. There is no heap-value CSE, general
receiver-phi lowering, pointer hoisting or prototype dependency invalidation here.
