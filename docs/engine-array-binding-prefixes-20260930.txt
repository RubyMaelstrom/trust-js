Closed lexical Array binding prefixes — 30 September 2026
=========================================================

Decision: retain. The complete examples/ejs/code.js solver takes 0.95% less
process wall time, with a paired 95% interval excluding parity. No independent
application timing, CPU or peak-RSS regression gate is crossed. This is a small
incremental gain; it does not establish a major engine-wide improvement or
close the broader Node performance gap. This experiment completes the current
optimization phase at the user's request.

The solver repeatedly binds captured pairs from Object.entries using
for (const [key, value] of ...). Its existing uncaptured-local DestructureArr
shortcut does not cover these runtime lexical bindings. Baseline diagnostics
record 244,063 pair bindings, 488,126 DestructureStepL helpers and 394,167
GetIter helpers. Even when the established intrinsic step path avoids result
objects, the generic opening still materializes an Array iterator.

The compiler now emits TryArrayBinding and ArrayBindingStep for fresh let/const
patterns containing at most eight flat identifiers or holes. Defaults, nested
patterns and rest stay on the established protocol. Opening peeks the source
and pushes a Boolean, with static stack effect (1,2); failure leaves the source
and full original GetIterator/step/close/error-handler sequence untouched.
Success retains the source and captured next function in the existing hidden
slots, then reads and initializes each binding in original forward order.
Uncaptured batching and interpreter parameter binding are unchanged.

The live proof requires the current realm's ordinary Array, intrinsic values
and next methods, enough own data indices for the entire prefix, and an ordinary
return lookup chain ending in absence or a nullish plain value. Accessors,
holes, exhaustion, customized iteration, proxies, host/typed/module/deferred
exotics and cross-realm native calls fall back before effects. A bounded
prototype walk also declines on uncertainty. Fresh binding initialization
cannot invoke author code between these reads.

Opening and steps preserve native-call depth, physical stack protection,
amortized GC ticks, entry/exit interruption, constructing state and newTarget.
A prefix that would cross the GC polling boundary, or has a pending proper-tail
transfer, declines before effects. Source and next owners remain in the original
hidden slots for frame lifetime. Retiring prior slot owners must be inert:
final host-callable owners retain the original destruction boundary. An empty
intrinsic iterator shell left by an earlier miss is accepted only when dropping
its target/prototype edges cannot retire their last external owner. The proof
counts shared target/prototype edges and aliases with the captured next slot.

Both VM dispatch and native checked-helper dispatch implement the new operations.
ARM64 and x64 retain their existing generic emission and recovery boundaries;
no raw object layout, executable-memory policy or host dependency changes.
The optional optimizing backend conservatively declines unsupported bodies;
it remains disabled in performance runs.
