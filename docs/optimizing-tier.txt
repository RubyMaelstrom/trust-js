Current implementation and decision
------------------------------------
The October 14 compiler work composes existing guarded bytecode inlining with the
whole-function backend. A separate Function optimizing slot owns an immutable
snapshot of the selected baseline Chunk. Remapped inline homes and shared logical
source registrations survive compilation and before-effect VM recovery. Retirement
selects the warmed baseline, including its inlines. The established frame-independent
splice eligibility remains the boundary; this is not arbitrary activation reconstruction.

Bounded integer-interval analysis now informs ToInt32 and element-index conversion
lowering. Constants and language operations establish facts; unguarded input samples
do not. A separate heap metadata must-analysis reuses own-data guards across effect-free
CFG paths for stable receiver identities. Mutable values and storage pointers are still
read live; callbacks, polls and generic slow paths invalidate metadata proofs. Diagnostic
switches TRUST_JS_OPT_JIT_RANGES=0 and TRUST_JS_OPT_JIT_HEAP_PROOFS=0 retain the prior
lowering. Frozen October 14 candidate v1 passed the full default/optional unit suites,
selected Test262 cases in four execution modes, and bounded differential testing.
See compiler-review-2026-10-14.txt for exact artifacts, scope and limitations.
Seven paired processes on the selected React/Angular/Vue/jQuery TodoMVC subset show
no application gain for candidate v1 with the optimizer disabled: median duration
+0.10%. Two untimed setup/transition CPU outliers remain unexplained. The separate
three-pair hot-mode screen also did not establish a gain. The backend remains off by default;
these results do not accept the later changes described below.
The previous measurements below remain historical evidence, not measurements of this
new compiler work.

The subsequent integer SSA tranche remains development code, integrated after focused
native tests, independent review and diagnostic ablations. Bounded backward register
demand retains sparse semantic I64 mirrors of proved exact safe-integer Numbers. Signed
bitwise results sign-extend and unsigned right shifts zero-extend; used ToInt32 and
element-index consumers avoid repeated floating conversions. Exact integer operands also
use mathematical I64 equality, ordering and truthiness, including loose equality when both
operands are proved Numbers. Mixed inputs retain checked coercions. Publication planning
preserves dirty owners only at the exact selected equality/not sites that invoke no helper.
Packed words and F64 copies remain eager, canonical publication/recovery is unchanged,
and private-write effects and independent completion roots govern reloads.
TRUST_JS_OPT_JIT_INT_SSA=0 skips mirror-demand
analysis and retains the interval-only lowering. This does not add Array-length proofs,
integer arithmetic or application performance acceptance.

Warmed monomorphic own-field overwrite sites now use a compact native shape/slot
probe. Only scalar cache facts are frozen: live receiver kind, shape, storage bounds,
descriptor flags and alias-aware owner transfers remain guarded. Changed facts use
the checked Set algorithm. Creation and polymorphic sites retain their dynamic probes.
TRUST_JS_OPT_JIT_COMPACT_STORES=0 restores the dynamic probe for comparison.
The focused fixture shrinks from 367 to 223 CLIF instructions and fits the unchanged
hot-compilation budget; this static result does not establish application repayment.
Release compilation validates finalized CLIF once before code generation instead of
repeating internal development checks. Debug/tests and TRUST_JS_OPT_JIT_VERIFY=1 keep
those repeated checks. Invalid input IR is still rejected before executable allocation.

Selected native PCs and bounded borrowed operands (2026-10-15)
--------------------------------------------------------------
TRUST_JS_OPT_JIT_BORROWED_OPERANDS=1 explicitly opts into borrowed operand windows.
Unset or 0 keeps them off, independently of the optional optimizing backend's own
feature and runtime controls. Eligible fresh ordinary entries can combine one private
LoadLocal; StoreLocal copy, or at most eight trailing consecutive LoadLocal inputs
immediately before an actual CallWithThis. Earlier call inputs remain ordinary owning
stack values. Prepared/resumable entries and continuations are excluded, as are inline
source positions, interior control-flow entries, polls and stress recovery boundaries.
Every consumed operation must be selected Native in the same original CFG block with
the certified stack depth and opaque floor. Other cases retain the established path.

During the borrowed phase, canonical or SSA source homes keep their owners. Each
original load retains its TDZ check unless its exact existing initialization proof
already removes it; checks and inputs stay in source order. Preparation validates the
running packed-owner ABI. A nonobserving bounded leaf checks the live owner words,
aliases, counts, overflow and last-owner conditions before committing any ownership
change. It neither allocates nor invokes GC, author code or final destruction. Failure
resumes the VM before the first selected load with its original owning prefix and dirty homes,
so original TDZ/error positions and effects are preserved. Success installs the owned
copy or materializes owning call inputs before invoking the unchanged call lowering at
its actual CallWithThis PC. No borrow crosses that call or another effect. Compiled artifacts retain no JavaScript
objects or extra owning value tables; runtime copies and call inputs retain their required owners.

The optional compiler builds its physical native-PC plan only after the final filtered
borrowed, literal-comparison and ordered-dispatch plans. It revalidates their exact
original operations and successor endpoints rather than retaining dead independent
labels for every bytecode. Actual entry, handler/resumption, abrupt-completion and
forced-deopt roots and the original end-PC mapping remain. A borrowed call preserves
its original call operation and endpoint+1 continuation. Cold cuts terminate in the
same invocation's VM before the original operation; they gain no fabricated native
outgoing edge. Consumed fusion interiors are not workload-unseen blocks. The original
Chunk, semantic CFG, stack/frame plans, positions and VM continuation metadata remain
complete. Invalid or conflicting certificates decline native compilation. Production
uses selected labels; the dense-label ablation is test-only, not a runtime switch.

Admission charges full original-graph scans, declined analysis attempts, bounded
minimum-path work and actual window/helper/recovery preparation. Replaced numeric
owner-check opportunities are removed; borrowing and omitted labels gain no new
semantic saved-work credit. Immutable owner-helper addresses are hoisted lazily only
when emitted, with their instructions still charged by the normal IR budget. Existing
entry guards, body bounds, configured thresholds, admission floors, prior cost coefficients
and hard IR/block caps remain unchanged. Admission distance is recomputed from the charged
estimate: selected-PC preparation adds 64 * (original_ops + 1) estimated work units, and
borrowed-window analysis/lowering/recovery adds its work when enabled. Targets and
eligibility can therefore change without a configured threshold override. Smaller graphs
or earlier compiler eligibility do not establish framework native entry,
compilation repayment or application performance acceptance.

Reuse and boundaries
--------------------
TRust already uses Cranelift 0.136.2 in its owned Wasmi hot-region compiler. TRust JS's optional
optimizing-jit feature adds direct codegen/frontend/native dependencies at that version; it
does not add a Wasmtime execution runtime or use WebAssembly as a JavaScript intermediate.
Cranelift provides machine-level SSA optimization, register allocation, ARM64/x64 lowering
and platform calling conventions. JavaScript type/shape/call specialization, semantic effects,
deoptimization, tier admission, GC roots, and host behavior remain TRust JS responsibilities.

The integration uses TRust JS's existing W^X ExecutableBuffer, native-code budget, cache leases,
active-frame residency marks and profiler registration. Indirect helper calls avoid external
linker assumptions; any unexpected relocation rejects compilation before code is published.
Cranelift verifies its IR and emits inline native stack probes. Compilation/unsupported-entry
failure leaves the established JIT/VM available. The feature and runtime selection are opt-in.

Execution contract implemented by the first backend
--------------------------------------------------
* One function-wide control-flow graph, including exception/finalizer destinations. No
  artificial loop-region selection or source/benchmark-name special cases.
* The same JitCtx ABI and native strictness save/restore as the established JIT. Every helper
  sees canonical packed owners, not unrooted integer copies of heap references.
* Scalar/numeric fast paths guard before effects. Failed guards execute the exact checked
  bytecode operation once; coercions, getters, proxies and callbacks cannot be replayed.
* Normal/abrupt stack prefixes remain exact after helpers consume inputs, including failure.
  Return and throw routing use shared bytecode completion algorithms. An ordinary return
  from a body that installs no handlers moves its packed result directly into a proven-empty
  destination, publishing remaining local/operand owners before exit. Occupied destinations,
  finalizers, iterators and completion resumes retain the checked router. The new backend
  selects bytecode-PC destinations; the existing JIT retains its machine-address adapter.
* Explicit loop interrupt/allocation-pressure safepoints preserve host cancellation and GC.
* Native callbacks and strict-mode proper-tail-call handoff retain the ordinary Call driver.
* Suspensions/disposal retain the existing native-slice/VM path until whole-function frame
  reconstruction covers them. This is a coverage boundary, not discarded functionality.
* Existing frame-independent speculative inline bytecode uses live callee, closure-context,
  Realm and receiver guards in this backend. A miss retains the original-call fallback.
  Hidden inline owners and source markers remain canonical across checked effects and VM
  recovery at the exact flattened bytecode boundary.
* Register-backed local SSA spans the entire function, with phi values at normal joins and
  loop backedges. A bounded may-dirty dataflow analysis selects canonical local stores before
  checked calls. Guarded slow paths publish the ORIGINAL incoming state; normal fast paths keep
  their new owning words in SSA. Helpers conservatively invalidate/reload tracked locals.
  Throw/finalizer dispatch reloads canonical state without re-publishing stale pre-call values.
  Operand owners now also use SSA, carrying a proven-live suffix above an opaque canonical
  prefix. A bounded fixed-point analysis joins suffix facts; edges publish owners that a
  less precise successor would otherwise forget. Helpers publish before entry and reload
  successful results only AFTER branching on the exception flag. Completion landing blocks
  reload their guaranteed suffix relative to the ACTUAL returned sp, never a saved depth.
  This is not yet ownership elision, heap speculation, general frame-state deoptimization,
  suspension/OSR reconstruction, or a moving-GC root-map implementation.
* Local loads, duplicates, stores and discards retain/move/release packed owners directly
  after live ABI validation for objects, strings, symbols and BigInts. All failing guards
  precede ownership effects. Last-owner destruction and lazy prototype materialization stay
  checked; native decrement never reaches zero. Self-assignment retains the incoming owner.
* Opt-in TRUST_JS_PERF_METRICS reports an optimizing_jit compilation subset (attempts, successes,
  declines, seconds, generated bytes). Its duration is nested inside total JIT compilation,
  not additive. Compilation counts do not establish dynamic native execution coverage.
* Immediate ToBoolean branches do not call a helper or publish local state. NaN and both zero
  signs remain false; heap values keep the existing IsHTMLDDA/ownership-aware path. Nullish
  peek branches test Undefined/Null identity for every tag, without copying/dropping an owner.
* Experimental TRUST_JS_OPT_JIT=hot keeps cold functions on the template tier. Fresh native
  entries count direct calls, host callbacks and recursion alike. The 2026-09-28 revision
  samples at four separated countdown expirations (at most 16 formal slots and 16 own-field sites), without turning
  on detailed feedback or redirecting native opcode fast paths. Stable Number/Boolean classes
  select guards BEFORE bytecode PC 0. Misses continue the same invocation through the VM.
  The semantic fixed-point analysis propagates guarded facts through actual CFG edges and
  audited private-slot effects; loop headers are not imaginary optimizing OSR entries.
  Warm ordinary own-data Number fields add result facts after live receiver, descriptor and
  Number guards at each access. Sampling reads only an existing monomorphic depth-zero cache
  and data descriptor; it never calls a getter, proxy or conversion. A miss resumes before
  the access with its canonical owners; callbacks and field changes are observed once.
  Generic bodies, environment-backed inputs and bodies above 256 ops are not candidates.
  Admission requires positive net eliminated tests after entry/result guards. Its initial work
  estimate uses 40 IR instructions per source op and 1024 observed removable tests per IR
  instruction, with at least 4096 observed calls. These are conservative estimates informed
  by diagnostic19, not measured future savings. TRUST_JS_OPT_JIT_HOT_AT overrides the distance
  for diagnostics but retains semantic and IR requirements. Actual lowered IR must fit the
  estimated envelope before code generation. A separate immutable Chunk must preserve exact
  source operation/name/slot/schema identity and compile successfully before publication;
  declines do not publish optimizing_code or invalidate callers. Old active owners remain
  protected. Function::code2 retains baseline bytecode inlining; a separate optimizing_code
  slot snapshots the currently selected canonical body without reserving or replacing the
  baseline slot. Shared source registrations retain logical inline identities until their
  final Chunk owner dies. The caller's active frame does not migrate during publication.
  It is not optimizing
  OSR, background compilation or a complete reoptimization policy. Optional runtime diagnostics
  count specialization bailouts separately from forced recovery stress. Eight misses retire
  a version: its slot immediately stops publishing addresses and invalidates raw call caches,
  while active frames and Rust leases keep their mappings until completion. Later dispatch or
  code pressure reclaims it, and subsequent compilation selects the template. Successful native
  entries pay no retirement counter. This conservative lifetime limit has no adaptive retry;
  application tests must measure its tradeoff for occasionally polymorphic functions.
  Experimental defaults remain off pending complete correctness/performance gates.
* Ordinary named field/method reads now use a bounded four-way native shape probe with up to
  five live prototype hops. Descriptor kind and slot bounds are checked after shape matches;
  the current data value is retained before any receiver is dropped. The frame stays in SSA
  through a hit. Cold/changed/accessor/Proxy/exotic/absent/last-owner/lazy-prototype cases
  retain the checked read. Arrays can only prove non-index named-property absence below an
  ordinary holder; their own named slots require the checked key-aware path. No getter result
  is cached and prototype replacement never reuses a cached object address.
  Warm monomorphic data sites use a compact constant-shape/slot guard chain instead of that
  general probe. Every hit still walks live prototype links and checks the current descriptor;
  no prototype identity or value is embedded. Polymorphic sites retain the bounded probe.
* Opt-in diagnostics additionally expose the existing process-wide call-cache epoch and the
  current thread's native-code eviction count. These have different scopes. Reading them does
  not add a counter update to calls or alter any invalidation/ownership behavior.

Current limitations — required work, not optional polish
--------------------------------------------------------
Migration review prompted by Ruby, 2026-09-28:
https://perryts.com/en/blog/cranelift-to-llvm/ (dated April 12, 2026; read with its
September correction). Perry attributes its initial regression to replacing inline
operations with opaque runtime calls. This is an engineering comparison, not evidence
for TRust JS's performance. Its corrected headline microbenchmark is not a browser target.

The concrete TRust JS gate is native-operation parity, not merely backend compilation or
matching return values. Rerun the established template tier's actual-path checks under
forced optimizing execution: packed reads/writes, small arrays, property creation with
equal non-interned keys and cached-layout ownership. Retain every failed counter and
test later assertions too; a first passing assertion does not close an entire case.
Heap16 addresses reads/overwrites, not creation/allocation. Those remaining boundaries,
plus calls/intrinsics, need explicit IR/counter evidence alongside whole-application
CPU, compile cost, code size and memory. Do not accept tiny-kernel wins as parity.

No blanket floating-point reassociation/contraction may be borrowed from the AOT example:
ECMA-262 e28783d5 Number::add/multiply specify separately rounded binary64 operations
(spec.html lines 2069 and 2170, #sec-numeric-types-number-multiply and
#sec-numeric-types-number-add). Integer narrowing needs overflow/range and negative-zero
proofs. Allocation fast paths need canonical roots and collection/refill boundaries;
shape/call or loop-hoisting facts must survive aliasing and observable mutations, or
guard/deopt before their effects. A stronger backend cannot supply these JS contracts.

The integration is NOT yet a mature optimizing tier. Guarded own-data reads/overwrites and
reserved named-field creation now have native paths; allocation, general computed-name
creation and exotic/observable cases still use checked helpers. Tracked local and operand
owners must publish at every possible observer. Function-wide code generation alone does not remove the dominant
object/call/ownership overhead. Do not enable by default or advertise a speedup from tests.

Required subsequent layers:
1. Extend the implemented local/operand SSA to prepared references plus precise frame states at
   guards, calls, exceptional edges, OSR and suspension. Unknown effects must invalidate facts;
   captured/eval-visible bindings and legacy activation reflection require explicit handling.
2. Feedback-driven value/shape/call specialization with checked descriptor/prototype/realm
   assumptions, inline property/element access, direct calls and speculative inlining.
3. Before-effect versus after-effect deoptimization, rebuilding all inlined frames without
   replaying effects or losing pending completions, lexical scopes, references or disposables.
4. Ownership/liveness analysis that removes redundant retain/drop/copy traffic. Register
   words alone are not roots in the current Rc cycle collector. Any future moving heap needs
   explicit spills/reloads and root maps; Cranelift does not infer JavaScript GC semantics.
5. Hotness and compile-cost-aware tiering, bounded retries and recompilation, OSR, code-cache
   integration and compile-time/code-size/GC attribution for each real application family.
6. ARM64 and x64 native execution gates, forced-tier differential tests, official Test262,
   default-tier regression tests, then interleaved release application measurements. Existing
   legacy conformance failures and recorded benchmark regressions remain separately open;
   this work does not waive them.

Experimental arbitrary-value own-data admission
------------------------------------------------
TRUST_JS_OPT_JIT_GENERIC_OWN=1 explicitly enables a structural specialization inside the
optional backend. It is off by default. Forced mode can select warmed ordinary own-data
reads/overwrites; hot mode records at most 32 named private-local/This sites at four separated
entry checkpoints. A site must keep the same truly monomorphic, cacheable, depth-zero scalar
IC state at every observation. Those observations select a version, never prove a live object.
The warmed immutable opcode/name/slot/cache graph is cloned together with the exact selected
states, and compilation validates the entire selection before using it. Indexed/prototype,
creation, polymorphic, missing, accessor, environment-homed and stale selections decline.

After validating that full snapshot, admission removes complete spans whose selected accesses
share no metadata checks. Those operations use the existing complete runtime paths and can
rejoin native execution after getters, setters, proxies or descriptor changes. Every selected
producer in a useful span remains, including its first access with no immediate savings.
Object-result producers required by the same comparison/branch proof also remain, with zero
structural credit and their existing result-guard cost. If selection changes, admission rebuilds
the proof and checks every retained state, read/write role and all four metadata elisions before
using it. Observer, poll and control-flow boundaries still delimit the spans.

Each CFG block begins with no metadata facts. Successful selected native checks can remove
later ordinary/shape/bounds/data tests for the same unchanged private receiver word. Unselected
operations, rebindings, helpers, polls and cleanup kill the facts. Reads still load current
values and retain their actual owners; stores keep their existing alias-aware owner transaction.
Neither boxes, retain/drop operations, values, pointers nor heap contents are credited as saved.
Required proof failure declines the candidate; no cheaper admission can silently fall back to
unproven helper rejoins. A live guard/owner miss at a retained selected access resumes before
that exact access, preserving any earlier completed read's owning RHS, and eight misses retire
the version as before. An omitted selection does not carry metadata facts across its helper.

Structural admission uses the minimum removed checks across reachable normal/explicit-throw
terminals and possible earlier checked-operation errors. Shortest CFG paths do not assume
loop trip counts; handler/resumption roots decline structural credit. The estimate excludes
host cancellation/resource termination and specialization misses, which remain separate
outcomes. The existing numeric benefit remains its older static-body estimate; mixed benefit
is not wholly a guaranteed saving per entry. Numeric credit obeys VALUE_FACTS, and HEAP_OPS=0
or COMPACT_STORES=0 disables structural selection. The 4096-entry floor, 256-op body bound and
40-IR/op bounded candidate compiler remain unchanged. Past entry counts are a work heuristic,
not prepaid savings or proof of future calls. Publication, actual entries, successful selected
accesses, VM recovery, compilation cost and workload phase must be reported separately. This
capability and forced emission fixtures establish no framework adoption or performance gain.
The 2026-10-15 pruning integration passed 73 focused ARM64 tests against the current sparse-PC
compiler and strict all-target Clippy with optimizing-jit+embed. The tests cover complete
accessor/proxy/readonly paths, callback collection, exact abrupt recovery, retained writable
guards and an Object-producing getter that changes to null before a previously folded branch.
See benchmarks/review-structural-pruning-validation-2026-10-15.json for exact source and artifact
bindings. This is correctness evidence; no release timing or cross-platform result is implied.

Compiler size, background work and execution observations
----------------------------------------------------------
Terminal recovery now shares a cold native block only when the helper kind, error epilogue,
exact dirty-local set and owning operand suffix agree. The originating bytecode PC remains
a dynamic argument. The shared block publishes the same owners and resumes the same VM
invocation; it does not spill clean register copies that may have become stale after a
callback. TRUST_JS_OPT_JIT_SHARED_RECOVERY=0 retains the previous per-site scaffolding.
This transformation is inside the optional backend, whose feature/runtime defaults remain off.

TRUST_JS_OPT_JIT_SHARED_OWNERS=1 separately selects shared scalar C-ABI retain/release leaves.
It is off by default. A live runtime layout proof gates the calls. Immediate values bypass
them; unsupported tags, null payloads, zero/overflow counts and last-owner release take the
existing checked path without mutation. Successful leaves change one strong count without
allocation, collection, author callbacks or final destruction. Multi-owner alias transactions
retain their existing implementation. Smaller emitted IR/code does not establish that the
extra native calls and spills improve throughput on an application.

TRUST_JS_OPT_JIT_BACKGROUND=1 experiments with bounded background code generation in hot
mode. JavaScript ownership, analysis and publication remain on the Agent thread; the worker
receives only compiler-owned Send data. Publication revalidates the originating baseline and
Realm. Pending/ready jobs remain within the shared quota, cancellation releases Agent owners,
and retirement preserves active native leases. See background-codegen-experiment.txt for
the complete queue, retry, shutdown and memory-accounting contract. It remains off by default.

TRUST_JS_OPT_JIT_DIAGNOSTICS=execution observes physical optimizing-native entries, exits,
terminal VM recoveries, specialization misses/retirement and the first eight emitted committed
data-property read/existing-overwrite, literal-comparison, ordered-case-dispatch or borrowed
owner-window PCs. One dispatch event counts the group, not skipped comparisons; a borrowed
event counts a committed local copy or owning call-input materialization, not its loads or
call completion. It excludes the broader Full-mode helper/owner instrumentation.
Whole-function and loop-continuation retirement use their respective live miss state. A normal
native ABI exit may include a completed VM recovery; subtract terminal VM normal completions
to identify normal exits through native control flow, except when counters saturate. Checked
helpers and author calls can still occur within that native control flow. Creation, computed
element operations and loop-scalar field operations are outside the selected site counters.
Compile-only mode adds no native counters. Code-owned diagnostic vector/string capacities are
included in retained metadata; the bounded directory keeps weak references, not JavaScript
owners. Full-mode shared-owner counters occupy separate slots from the eight execution sites.
All runtime diagnostic modes perturb emission and may change compiler-budget admission, so
their runs are not performance acceptance measurements.

Object-valued fields and exact Null comparisons
------------------------------------------------
TRUST_JS_OPT_JIT_OBJECT_FIELDS=1 extends the experimental GENERIC_OWN selection
with at most 16 Object-valued own-data read sites, drawn from its existing bounded
stable-cache observations. Both switches remain off by default. Selection requires
an exact Object mask across four property checkpoints, a stable monomorphic
own-data cache, and enabled value facts and heap/compact-store operations.
Every selected Object native read checks the live value's exact Object tag before
retaining its owner. The proof describes that copied value, not an immutable
property or prototype. A changed receiver, descriptor or category recovers before
that read with all completed effects and owners preserved. Effects invalidate heap
metadata proofs; copied Object values may remain proved when private-slot effects
permit it.

Object and Null are different ECMAScript types even for callable, revoked-Proxy
and IsHTMLDDA objects. Strict comparisons can therefore establish a Boolean and
prune an adjacent dependent conditional within the same block under the guarded
Object proof. Type facts are computed on the original CFG with both edges; native
reachability and structural benefit then use the same feasibility certificate.
Independent handler and resumption roots, unsupported joins and cyclic selected
guard blocks remain conservative. The proof does not eliminate required
retain/release operations or invoke a getter, Proxy trap or conversion while
collecting feedback. Generic strict comparisons remain available after recovery.

Inside the optional optimizer, a settled exact-Null operand also selects a
compact strict-equality/inequality operation for an arbitrary peer. It compares
canonical packed identity, consumes the peer's owner, and produces a canonical
Boolean without conversion, getters or Proxy traps. A last owner or unsupported
layout takes the original checked operation once, before changing its operands.
TRUST_JS_OPT_JIT_STRICT_NULL=0 retains the previous lowering. Whole-function
VALUE_FACTS=0 supplies no exact-Null proof; a loop continuation may still have its
own independently guarded entry facts.

Lowering and benefit estimation share the same exact-Null and known-stack-suffix
selection. The generic peer has one dynamic owner-classification check; a proved
copyable peer removes it. The comparison itself earns no added credit, and an
opaque stack suffix earns none for an unchanged checked operation. Entry-guard
costs, the 256-op hot bound, the 4096-entry floor and the compiler IR caps remain
unchanged. Fitting within a cap does not establish publication, native execution
on a framework, or repayment of compilation work.

Bounded literal-string comparison and ordered case dispatch
-----------------------------------------------------------
The optional backend now fuses a private-local read, immutable String
constant, strict equality/inequality and conditional branch when the original CFG
and owning stack certificate permit it. It borrows the current local and the exact
Chunk's literal without creating two temporary owners. The first LoadLocal's settled
initialization proof can omit its Empty test; absent or exhausted proofs retain VM
recovery before the original start, including reversed Const/load order and TDZ position.
Non-Strings do not match a String literal and invoke no conversion or author callback.
Engine text, String views and lone surrogates retain exact code-unit equality.

Consecutive equality cases over the same unchanged local can share one borrowed
source-order helper and native ordinal dispatch, bounded to 128 cases per group.
The first duplicate selects its original destination. Original case Jumps, bodies,
default and fallthrough remain; a matching formerly cold case still recovers before
its original Jump. External/interior entries, handlers, cleanup roots, polls and stress
recovery boundaries cannot be consumed. Each outcome uses its own original branch
stack/dirty state, retaining opaque canonical owners. Longer chains split into ordered
groups. Generated code adds no JavaScript owners or owning literal tables.

Hot mode can identify literal-only and zero-formal bodies through this complete
certificate. Conservative credit is one constant-owner work unit after both original
reads: two retain/release operations less one String tag check per comparison. Grouping
adds no semantic credit or case-body savings. Full original certificate/group scans,
attempted value solvers (including exhausted results), and bounded helper/switch/owner
publication work remain charged. Small normal/abrupt minima combine guards once; large
observed-region branch unions remain explicitly provisional opportunity heuristics.
Feature/runtime defaults, threshold overrides and hard IR/block limits are unchanged.
Execution diagnostics distinguish single comparison sites from one event per executed
group; that event does not count skipped comparisons or case-body work.
