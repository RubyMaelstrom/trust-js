Observed-region native emission experiment (2026-10-14)

TRUST_JS_OPT_JIT_OBSERVED_REGIONS=1 separately opts into selecting native
emission from exact-version frozen baseline CFG-region entry provenance.
TRUST_JS_OPT_JIT_COVERAGE=1 must collect that provenance. Both controls remain
off by default; the optimizing-jit feature and optimizing runtime selection
remain separately opt-in. No admission limit or instruction/block budget is
increased. In particular hot bodies above 256 operations still stay on the
established tier: this stage does not admit retryNode, renderElement,
pushStartInstance or performWork from the pinned large React SSR workload.

The exact baseline entry must have been entered. Entered and Unknown blocks
keep native lowering; only UnseenInWindow block entries become terminal VM
cuts. Unseen is a bounded historical collection window, not unreachable code,
normal completion or a prediction of future behavior. IC absence is irrelevant.
No interior opcode in an unselected block is lowered. Original PC labels and
every handler/finalizer/abrupt destination survive; all legal targets are block
leaders, including lexical cleanup pads before author catch/finally bodies.

The full original Chunk and both original CFG edges feed all existing frame,
stack, value, range and heap analyses. These analyses remain conservative.
Recovery publishes only the original exact dirty packed-local slice and known
owning operand suffix relative to actual sp. Opaque prefix owners are canonical;
clean/dead SSA copies and numeric mirrors are never revived. BeforeEffect
recovery resumes the same call at the original cut PC and returns directly to
the native success/error epilogue. A checked-helper throw first follows existing
native unwind/landing reloads. No parameters, prefix effects, environment,
references or completion handlers are reconstructed as a new function call.

Global disposal, suspension and fragment exclusions apply to the entire original
body even when wholly in a cold unselected tail. Loop continuations are unchanged.
The explicit DEOPT_AT stress hook retains its full-body emission policy so its
requested original boundary is not replaced by an earlier coverage cut.

At a hot checkpoint one snapshot is frozen before estimating benefit and that
same snapshot is copied into the candidate. Each cut is a benefit terminal;
no VM-remainder work receives native credit. Existing <=256-op/no-handler
structural shortest-path bounds remain. Numeric guards are conservatively
charged and potentially abrupt numeric sites cannot receive later-op credit.
Candidate lowering checks positive cut-aware benefit again before publication.
The compilation estimate still charges the full original body, not a guessed
discount for omitted work. Large-body admission is a later policy stage requiring
actual workload coverage, reduced complete IR and honest repayment evidence.

Execution/full diagnostics separately count observed_region_vm_exits. These
ordinary exits never increment optimizing_misses or request eight-miss retirement.
Static diagnostic metadata identifies the frozen source version, selected original
opcode count and cut-block count; it is not an execution-frequency estimate.
Disabled/compile diagnostics add no native counter instructions. Frozen coverage
and selection contain no JS objects, environments or executable owners; backend
workers continue receiving only owned Send compiler state.

New tests explicitly prove native entry, reached original cut PCs, omitted
interiors, real IR/code-size changes, owning RHS through GC and throw, cold
iterator/finalizer landing dispatch and IteratorClose precedence, saved lexical
References/mapped arguments/eval, per-iteration scopes and prefix/default effects,
labelled completions, shared graph/foreign Realm/caller-handler floor, dead inline
callee destruction before a later cut, global tail exclusions, early-cut benefit
decline, and real bounded background hot publication/independent retirement.
Forced semantic fixtures do not prove hot admission or framework performance.
Source-only at initial freeze; runtime/build results must be recorded separately.
